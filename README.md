## 小组 Git 协作规范

本仓库由小组成员协作维护，遵循以下规则：

### 1. 分支策略
- `main`：始终保存**能够运行的稳定版本**，禁止直接向 main 提交未验证代码。
- 每名成员使用自己的功能分支开发，命名如 `feature-order`、`feature-ai`、`feature-test`（按本人分工命名）。

### 2. 任务与合并
- 每项任务先在 README 的「任务记录表」或 GitHub Issues 中登记：**负责人 + 目标**。
- 任务完成后，通过 **Pull Request（合并请求）** 合入 `main`，或记录明确的合并记录。
- 合入前需至少一名其他成员审阅并留下具体意见。

### 3. 提交要求
- 每名成员至少完成 **5 次有实际内容的提交**，且提交分布在**至少 2 个不同时间段**。
- 禁止在任务结束前一次性上传全部代码。
- 提交信息须说明本次完成的内容，推荐格式：
  - `feat: 增加工单状态更新`
  - `fix: 修复登录超时问题`
  - `docs: 补充接口说明`
- **禁止**使用 `update`、`修改一下` 等无法判断内容的描述。

### 4. 审阅要求
- 每名成员至少**审阅一次**其他成员的代码或合并请求，并在 PR 中留下具体意见。

### 5. 提交规范
- 不得代替其他成员提交代码。
- 共同编程时，在提交说明中标注共同作者（`Co-authored-by:`），或在协作记录中说明。

### 6. 最终交付
- 提交最终 `git log --stat` 或仓库提交记录截图。
- 在 README「成员贡献表」中列出每名成员的实际贡献。
